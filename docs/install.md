## Configuring a host

### How modules are enabled

Most modules expose an `enable` option under `systemSettings.*` or `userSettings.*`; a few also take values (hostname, kernel, mount points, credentials). Hosts turn on only what they need in `hosts/<name>/configuration.nix`:

```nix
systemSettings = { desktop.enable = true; audio.enable = true; ... };

home-manager.users.rodri.userSettings = {
  shell.enable = true;
  programs.noctalia.enable = true;
  ...
};
```

Packages and apps live in one module each, so you can install them individually.

### Adding a machine

1. Create `hosts/<name>/configuration.nix` (+ `hardware-configuration.nix`; `hardware/<name>.nix` is optional).
2. Enable only the modules that machine needs.
3. Run `sudo nixos-rebuild switch --flake .#<name>`; the flake auto-detects it.

### Hardware abstraction

Vendor knobs live in `hosts/<name>/hardware/<name>.nix`:

```nix
{ cpuVendor = "intel"; gpuVendor = "igpu_intel"; }
```

Both values default to `"other"` when the file is absent, so a new host evaluates without vendor-specific tweaks. `modules/system/hardware/cpu/*.nix` and `gpu/*.nix` apply settings via `mkIf` based on `hardware.pc`.

## Storage, encryption and secrets

### Disk layout and impermanence

`hosts/<name>/disko.nix` declares the disk layout: a GPT with an EFI partition (`/boot`), swap (also `boot.resumeDevice`) and one btrfs partition with the subvolumes `root`, `persistent`, `home` and `nix`. Mount options (`compress=zstd:3,noatime`) are declared there, so disko hosts skip `systemSettings.btrfs`.

With impermanence enabled, the root is wiped the native btrfs way. `modules/system/impermanence.nix` runs a `wipe-root` service in the systemd initrd: it moves the current `root` subvolume to `old_roots/<timestamp>` (older than 30 days is deleted) and creates a fresh `root` before `sysroot.mount`. As a result, `/`, `/etc` and `/var` are wiped on every reboot, while `/home`, `/nix` and `/persistent` survive.

Without impermanence, no wipe service is installed and the same subvolumes are simply mounted. What survives a reboot is declared with [impermanence](https://github.com/nix-community/impermanence), gated by `systemSettings.impermanence.enable` and `systemSettings.impermanence.persistentStoragePath` (default `/persistent`).

`hardware-configuration.nix` is generated by `nixos-generate-config` and is **not edited**, but it is also **not imported** on disko hosts: `hosts/<name>/hardware.nix` keeps only the detected kernel modules/CPU settings, so regenerating it cannot reintroduce conflicting mounts.

Persistence is distributed. Each module declares the state it needs, but only when both impermanence and the module itself are enabled. Hosts without impermanence are not affected. The pattern used across `modules/system/` is:

```nix
config = lib.mkIf cfg.enable {
  # ... the module's regular settings ...

  # Impermanence: <why this path must survive a reboot>.
  environment.persistence.${config.systemSettings.impermanence.persistentStoragePath} =
    lib.mkIf config.systemSettings.impermanence.enable {
      directories = [ "/var/lib/example" ];
      files = [ "/etc/example.conf" ];
    };
};
```

State kept across reboots, by module:

| Module | Persisted state |
|---|---|
| `impermanence.nix` (base) | `/etc/machine-id`, `/var/log`, `/var/lib/nixos`, `/var/lib/systemd/coredump` |
| `hardware` | `/var/lib/bluetooth` (paired devices) |
| `networking` | `/etc/NetworkManager/system-connections`; SSH host keys only while `services.openssh.enable` |
| `networking/warp` | `/var/lib/cloudflare-warp` (one-time `warp-cli` registration) |
| `boot/secureboot` | `/var/lib/sbctl` (Secure Boot keys, needed to boot in user mode) |
| `packages/ollama` | `/var/lib/ollama` (pulled models; static `ollama` user so systemd does not migrate the bind mount to `/var/lib/private/ollama`) |
| `packages/virtualisation/libvirt` | `/var/lib/libvirt` (imperative VMs) |
| `desktop` | `/var/lib/colord` only while `services.colord.enable` |

The host enables both gates in `hosts/<name>/configuration.nix` and imports `./disko.nix`:

```nix
imports = [ ./hardware.nix ./disko.nix ];

systemSettings = {
  disko = {
    enable = true;
    # Per-host encryption choice (defaults: both false):
    # luks.enable = true;
    # luks.tpm2 = true; # requires luks.enable
  };
  impermanence.enable = true;
};
```

No UUID or device is hardcoded. disko declares `disko.devices` for the whole disk, and the wipe service derives its device from `config.fileSystems."/".device`. The persistent subvolume name must match its mount point: `persistent` is mounted at `/persistent`. `hosts/nixyo/disko.nix` takes `device` as an argument with a placeholder default (`/dev/disk/by-id/DISKO_DEVICE`), so flake evaluation works without a disk. Running its disko script without `--argstr device` fails loudly.

### LUKS and TPM2

`systemSettings.disko.luks.enable` wraps the btrfs partition (root/persistent/home/nix) in LUKS named `cryptroot`; `/boot` and swap stay plaintext. `systemSettings.disko.luks.tpm2` is independent per host but requires LUKS. Both default to `false`, so existing hosts are unchanged.

The manual install passes the LUKS passphrase to disko through `--argstr passwordFile "$LUKS_KEY"`. The passphrase file lives on the keys USB and is never stored in the repo.

With `systemSettings.disko.luks.tpm2`, crypttab gets `tpm2-device=auto,tpm2-pcrs=7`. PCR 7 tracks the Secure Boot state. Fresh keys are still in Setup Mode during the install, so the TPM2 token cannot be enrolled then. Leaving Setup Mode changes PCR 7 and would make the token unusable on the next boot. Enrollment waits until Secure Boot is enabled and the first login succeeds.

Auto-unlock adds roughly 0.2 to 1 s to boot. Encryption itself costs a few percent I/O on CPUs with AES-NI, more without it. Without TPM2, boot waits for the passphrase prompt.

If firmware or keys change later, re-seal manually:

```bash
sudo systemd-cryptenroll --wipe-slot=tpm2 --tpm2-device=auto --tpm2-pcrs=7 /dev/disk/by-partlabel/root
```

### Password secrets (agenix)

`/etc/shadow` lives on the wiped root subvolume, so passwords come from two encrypted secrets instead:

| Secret | Feeds | Recipient in `agenix-rules.nix` |
|---|---|---|
| `secrets/nixyo-root-password.age` | `users.users.root.hashedPasswordFile` | `age` |
| `secrets/nixyo-rodri-password.age` | `users.users.<user>.hashedPasswordFile` | `age` |

Both secrets use the same `~/.ssh/id_ed25519_agenix` key and are already encrypted. To change a password:

```bash
openssl passwd -6
echo '<hash>' | nix run github:ryantm/agenix -- -e secrets/nixyo-root-password.age
echo '<hash>' | nix run github:ryantm/agenix -- -e secrets/nixyo-rodri-password.age
```

`passwd` alone is not enough because `/etc/shadow` is wiped on every boot. During the manual install, the agenix key is staged at `/home/rodri/.ssh/id_ed25519_agenix` before `nixos-install`, and `/home` stays mounted in the initrd (`neededForBoot = true`). That lets agenix decrypt the secrets during activation and `users` write the hashes in the same run. The install uses `--no-root-password`, so no password is asked afterwards.

## Fresh install

Installation is manual and **DESTRUCTIVE**. Secure Boot keys are always generated fresh, so the firmware must be in Setup Mode at install time. The only interaction after the install is enabling Secure Boot in firmware and enrolling the TPM2 token after the first login.

### 0. Prepare

1. Back up the target disk.
2. Prepare two USB sticks (simplest option):
   - **USB A**: the NixOS ISO written with `dd` to the **whole device**;
   - **USB B**: this repo (`nixdots/`), `id_ed25519_agenix` (private key) and a file containing the LUKS passphrase used by disko.

   A single stick with a data partition after the ISO works too, but two sticks are simpler.
3. BIOS -> Secure Boot -> **Clear keys / Setup Mode**, Secure Boot disabled, and no existing keys in `/var/lib/sbctl` of the installer environment.
4. Note the target disk's `/dev/disk/by-id/...` path.

### 1. In the installer

Boot the ISO from USB A in Setup Mode, then:

```bash
# Mount the data stick
lsblk -f
sudo mkdir -p /run/media/keys
sudo mount /dev/disk/by-label/<LABEL_USB_B> /run/media/keys

REPO=/run/media/keys/nixdots
AGENIX_KEY=/run/media/keys/id_ed25519_agenix
LUKS_KEY=/run/media/keys/luks.key
M=/mnt

# Identify the target disk. Never assume /dev/nvme0n1
lsblk -d -o NAME,SIZE,MODEL,SERIAL
ls -l /dev/disk/by-id/
DISK=/dev/disk/by-id/<id-do-nvme>
RAM_GB=$(awk '/MemTotal/ {val=$2/1024/1024; print int(val) + (val > int(val))}' /proc/meminfo)

# 1. Generate and enroll fresh Secure Boot keys while in Setup Mode.
#    sbctl verify will still report unsigned ISO modules here; expected.
sudo sbctl create-keys
sudo sbctl enroll-keys --microsoft

# 2. DESTRUCTIVE: wipe the disk and create GPT/swap/btrfs/LUKS/subvolumes.
#    Swap = min(RAM, 32 GiB); override with --argstr swapSize 8G.
sudo nix --experimental-features "nix-command flakes" run \
  github:nix-community/disko/latest -- \
  --mode disko \
  --argstr device "$DISK" --argstr ramGb "$RAM_GB" \
  --argstr luks true --argstr tpm2 true \
  --argstr passwordFile "$LUKS_KEY" \
  "$REPO/hosts/nixyo/disko.nix"

# 3. Refuse to build if /home will not be mounted in the initrd. Without this,
#    agenix cannot read the key during activation and both accounts end up locked.
grep -q 'fileSystems."/home".neededForBoot = true;' \
  "$REPO/hosts/nixyo/configuration.nix" || {
    echo "ERROR: missing neededForBoot on /home" >&2
    exit 1
  }

# 4. Stage the agenix key in the target BEFORE installing. This is what lets
#    activation decrypt the password secrets inside the chroot.
sudo install -d -m 0700 -o 1000 -g 100 "$M/home/rodri/.ssh"
sudo install -m 0600 -o 1000 -g 100 \
  "$AGENIX_KEY" "$M/home/rodri/.ssh/id_ed25519_agenix"

# 5. Keep a local checkout for future rebuilds (also before installing).
sudo install -d -m 0755 -o 1000 -g 100 "$M/home/rodri/nixdots"
sudo cp -a "$REPO"/. "$M/home/rodri/nixdots/"
sudo chown -R 1000:100 "$M/home/rodri/nixdots"

# 6. Lanzaboote reads signing keys from /var/lib/sbctl inside the chroot;
#    keep the same copy under /persistent for later rebuilds.
sudo install -d -m 0755 "$M/var/lib/sbctl" "$M/persistent/var/lib/sbctl"
sudo cp -a /var/lib/sbctl/. "$M/var/lib/sbctl/"
sudo cp -a /var/lib/sbctl/. "$M/persistent/var/lib/sbctl/"

# 7. Install. Passwords come from agenix; no root password is requested.
sudo nixos-install --flake "$REPO#nixyo" --no-root-password

# 8. Verify BEFORE rebooting: expect "$6 106" for both users, never "! 1".
awk -F: '$1 ~ /^(rodri|root)$/ {print $1, substr($2,1,3), length($2)}' \
  "$M/etc/shadow"
```

If step 8 shows `! 1`, stop: the agenix key was not readable during activation. Re-check step 4 and run `nixos-install` again. Do not reboot with locked accounts.

The resulting fileSystems/swapDevices use GPT partlabels, so the installed system never depends on the disk path given to disko.

### 2. First boot

1. Reboot (removing the USB sticks is fine) and set BIOS -> Secure Boot = **Enabled** before or during this reboot.
2. There is no TPM2 token yet, so LUKS asks for the passphrase once. Log in as `rodri` with the password from the secret; `root` also comes from agenix.
3. Verify:

```bash
ls -l /run/agenix/nixyo-*-password
sudo cryptsetup status cryptroot
sudo sbctl verify
sudo awk -F: '$1 ~ /^(rodri|root)$/ {print $1, substr($2,1,3), length($2)}' /etc/shadow
```

4. Now that Secure Boot is enabled and PCR 7 is final, enroll TPM2 (no `--wipe-slot` is needed because no token exists yet):

```bash
sudo systemd-cryptenroll --tpm2-device=auto --tpm2-pcrs=7 /dev/disk/by-partlabel/root
sudo systemd-cryptenroll /dev/disk/by-partlabel/root | grep tpm2
```

From then on LUKS unlocks automatically. If firmware or Secure Boot keys change later, re-seal as shown in [LUKS and TPM2](#luks-and-tpm2).

On the first boot, the subvolume created by disko moves to `old_roots/` and a fresh `root` is created. That is expected. `old_roots` is kept for 30 days as a manual rollback point: rename a snapshot back to `root` to recover it. NixOS generations remain in `/nix`.

`nix eval --json` on `environment.persistence.<path>.directories` currently trips [impermanence#305](https://github.com/nix-community/impermanence/issues/305). Use `nix eval --apply 'ds: map (d: d.directory) ds'` instead. Evaluation and builds are unaffected.

## Deploy

```bash
sudo nixos-rebuild switch --flake .#nixyo
# or, with systemSettings.nh enabled (NH_FLAKE points at this repo):
sudo nh os switch
```

## Project templates

`flake.nix` exposes flake templates for scaffolding new standalone projects:

```bash
nix flake init -t .#base          # local
nix flake init -t github:rodrig20/nixdots#base   # from anywhere
```

Currently available:

| Template | Purpose |
|---|---|
| `base` | Minimal `flake.nix` (`nixpkgs` input + empty `devShells.default`) with a `.envrc` for direnv; extend it as you go |

Each generated project is a single self-contained `flake.nix` with no pre-defined structure. It ships a `.envrc` for **direnv** (enabled via `userSettings.programs.direnv`): `cd` into the project and its devShell packages join your *current* shell (zsh aliases, starship, fzf stay intact). Authorize it once per project with `direnv allow`.

## Binary cache

Local store paths are published to a self-hosted cache on GHCR, so rebuilds download them instead of recompiling. No third-party cache is involved.

- **Publish**: `.github/workflows/publish-cache.yml` runs the `nixcache-oci` pipeline (`lib/cache-builder.sh`) on every push to `main` that can change the closure. It builds the flake outputs, keeps only paths that no upstream cache signs, signs them with `NIX_SIGNING_KEY` and uploads them as OCI blobs to `ghcr.io/rodrig20/nixdots/nix-cache`. `.github/workflows/gc-cache.yml` prunes the index weekly with a 30-day retention period. The scheduled `auto-update` publishes through this pipeline after its commit. A push using `GITHUB_TOKEN` does not trigger other workflows, so this step keeps the cache current.
- **CI**: `pr-check.yml` and `auto-update.yml` start the same proxy for the job (`start_self_substituter` -> builds -> `stop_self_substituter`). PRs and the daily update then download previously published paths instead of rebuilding them. The proxy pulls anonymously from the public package, with no token. If the cache is missing or empty, lookups return 404 and Nix falls back to `cache.nixos.org` as before.
- **Consume**: `systemSettings.nixcache.enable` (`modules/system/nixcache.nix`) runs `services.nixcache-proxy`. It exposes the GHCR index as a substituter on `localhost:37515` and streams NARs from the registry. The public key is pinned in `flake.nix` `nixConfig`, so CI and NixOS trust the same signatures.

One-time setup:

1. Generate the key pair and store the secret on GitHub (Settings -> Secrets and variables -> Actions -> `NIX_SIGNING_KEY`); the public half is already pinned in `flake.nix`.
   ```bash
   nix key generate-secret --key-name rodrig20-nixdots   # -> NIX_SIGNING_KEY secret
   ```
2. After the first publish run, set the package `ghcr.io/rodrig20/nixdots/nix-cache` to **Public** so the proxy can pull it anonymously.
